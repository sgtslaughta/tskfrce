# v2 Project 5b: Chat — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A thread on every chore (proof photos and send-back notes appear there), one private parent↔kid thread per kid, and a family group chat, with unread counts for parents and kids.

**Architecture:** Three new tables (`threads`, `thread_messages`, `thread_reads`) owned by one service, `app/services/chat.py`, which also enforces who may read/post. Chore threads are created lazily on first read/post. System messages (photo added, sent back with note, approved) are written by the existing 5a routes via one helper. Clients poll (15 s) — the legacy websocket stack is not reused (Claude's call: smaller surface; revisit if polling cost shows up). Legacy messaging tables are left untouched.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, pytest; Next.js + Mantine + TanStack Query, Jest.

**Spec:** `docs/superpowers/specs/2026-10-21-v2-today-chores-chat-design.md` (Part 5b + "Data model").

Prerequisite: Projects 2, 5a, 3, 4 merged into `feat/v2-teen-redesign`. Commands as in the Project 2 plan.

## Global Constraints

- Thread kinds: `chore` (one per chore instance, `task_id`), `private` (one per kid, `kid_id`), `family` (exactly one).
- Access: parents read/post everywhere. A kid reads/posts: their own `private` thread; the `family` thread; `chore` threads where `kid_chores_filter(kid)` includes the task. Everything else → 404 (not 403, don't reveal existence).
- Message: `body` 1–2000 chars (trimmed) and/or one `photo_id`; at least one required (422). Photos reuse 5a's `chore_photos` storage/serving rules for chore threads; for private/family threads store under `DATA_DIR/chat_photos` with the same re-encode (EXIF stripped) and authenticated serving.
- System messages: `author_id = NULL`, `kind = "system"`, body like "Photo added", "Sent back: <note>", "Approved · +15". Written in the same transaction as the action.
- Unread = messages in a thread newer than the reader's `thread_reads.last_read_at` and not authored by the reader. Opening a thread marks it read.
- Polling: thread view 5 s while open; unread counts 15 s. Stop polling when the tab is hidden (`refetchIntervalInBackground: false`).
- No push/email, no typing indicators, no read receipts beyond unread counts, no edit; delete own message within 5 minutes (Claude's call; parents can delete any).
- Copy tone as elsewhere. Files < 500 lines.

## Review Focus

1. **Sibling snooping:** Leo requests Maya's private thread or a chore thread only Maya is on → 404. (Task 1 test.)
2. **Shared chore thread:** Race/Team participants all see the shared chore's thread. (Task 1 test.)
3. **Empty or huge messages:** whitespace-only → 422; 2001 chars → 422. (Task 1 test.)
4. **Unread math:** own messages never count as unread; system messages count for everyone. (Task 1 test.)
5. **Long threads on a phone:** 500 messages render with "Load earlier" (page size 50) without freezing; composer stays visible above the keyboard. (Task 2/3 test for paging.)
