# v2 Project 6: End-to-end tests in the device lab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the whole product works together on a simulated home network: chores gate real (simulated) kid devices, approvals and screen time bring them back online, shared chores and send-back behave, the box-offline warning fires — plus a browser pass over every screen in light/dark at desktop and phone widths.

**Architecture:** Extend the existing Docker lab (`lab/docker-compose.lab.yml`: router, fake internet, backend, blocker, `kid1`/`kid2`/`parent` hosts) with (a) API-level **journey tests** in Python that act as parent and kids from inside the lab and assert real connectivity with `scripts/lab.sh check`, and (b) a `frontend` service plus an `e2e` Playwright container on the lab network for **browser journeys and screenshots**. CI's existing `lab` job runs both and uploads screenshots.

**Tech Stack:** Docker Compose, pytest, bash; Playwright (`@playwright/test`, new frontend devDependency, pinned) in the official `mcr.microsoft.com/playwright` image of the same version.

**Spec:** both specs in `docs/superpowers/specs/2026-10-21-*` (all behaviors), lab docs `lab/README.md`.

Prerequisite: Projects 1, 2, 5a, 3, 4, 5b merged into `feat/v2-teen-redesign`. Run lab tests: `cd blocker && RUN_INTEGRATION=1 python -m pytest tests/lab -v` (needs Docker with IPv6 bridges; see CI job).

## Global Constraints

- Journeys run against the real stack in the lab; no mocks. Kids act from their own lab host (`kid1` 10.99.0.11, `kid2` 10.99.0.12) so device-by-IP kid login works; the parent acts from `parent`.
- Connectivity = `scripts/lab.sh check <host>` (curl to the fake internet). Waits use the existing `wait_for` with lab intervals (scan/reconcile/resist = 5 s); every wait ≤ 60 s except the box-offline check (≤ 150 s: 90 s stale + polling).
- Each journey starts from a known state: a fresh family created by a session fixture (parent `labparent`), kids/devices/chores created per test and deleted after; no test depends on another's order.
- Browser tests use a parent account; screenshot every v2 route in light and dark at 1280×800 and 360×740; fail if `document.documentElement.scrollWidth > window.innerWidth` on any route, or any console error.
- Pin versions: `@playwright/test` and the image tag identical (e.g. `1.48.2` / `v1.48.2-jammy`).
- No production code changes unless a journey exposes a bug — then fix it in a separate commit with a regression unit test, and say so in the report.
- Files < 500 lines; split journeys by area.

## Review Focus

1. **Flaky timing:** journeys must poll with `wait_for`, never fixed sleeps longer than the lab interval. (Task 1.)
2. **Leftover state between tests:** a failed test must not leave a device blocked for the next (cleanup in `finally`/fixtures). (Task 1.)
3. **Kid login by device IP:** if kid1's device isn't discovered yet, the journey waits for discovery rather than failing. (Task 1.)
4. **Screenshots in CI:** uploaded even when tests fail. (Task 3.)
5. **Time windows:** the bedtime journey sets a window relative to the lab's current time in the family timezone, not a hard-coded hour. (Task 1.)

### Task 1: API journey tests

**Files:**
- Create: `blocker/tests/lab/journey.py` (helpers: `parent(method, path, json=None)`, `kid_login(host, kid_id, pin) -> token`, `kid(host, token, method, path, json=None, files=None)`, `online(host) -> bool`, `wait_online(host, want: bool, timeout=60)`, `make_kid(name, pin, host) -> dict` (creates kid, waits for the host's device, assigns it), `cleanup()` registry)
- Create: `blocker/tests/lab/test_journey_chores.py`, `test_journey_economy.py`, `test_journey_box.py`
- Modify: `scripts/lab.sh` only if a needed primitive is missing (e.g. `kid-curl <host>`), keep its style
- Test: the files above

Journeys (one test each):
- **Chore gate:** kid1 with one daily chore → offline; kid submits → still offline; parent approves → online; balance = chore points.
- **Subtasks + photo + send back:** chore with 2 subtasks and needs-photo; submit before ticking → 409; tick both, upload a JPEG from kid1, submit; parent sends back with a note → kid sees `last_note`, still offline; resubmit with a new photo; approve → online; Needs-you showed type `redo` with attempt 2 before approval.
- **Race:** kid1 + kid2 race chore; kid2 submits, parent approves → **both** online; kid1 sees `taken_by`.
- **Team:** 30 points, both kids → 15 each after approval.
- **Screen time:** switch on, kid1 has ≥ price points, pending chore keeps it offline; request 15 min → still offline; deny → offline, balance unchanged; request again, approve → online; balance reduced.
- **Bedtime beats screen time:** allowed window that excludes now (family tz) → approved screen time doesn't bring kid1 online.
- **Reward + celebration:** reward priced within balance; request, approve; `/kid/celebrations` has a big reward item; seen clears it.
- **Level up:** award enough points to reach Lv2 → celebration with title; profile shows Lv2.
- **Chat:** kid1 posts in its private thread; parent unread ≥ 1; kid2 gets 404 for kid1's private thread.
- **Box offline:** `docker compose stop blocker` → `/api/v1/blocker` `online: false` within 150 s and kid1 fails open (online); start blocker → `online: true`.
