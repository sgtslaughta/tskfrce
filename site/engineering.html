Engineering overview

For contributors and technical readers. Parents: the guide is for you.

Architecture

Everything runs on one Linux computer in the home, next to an ordinary router. Four containers: the web app, the API, a small ntfy server for kids' phones, and the blocker on the host network.

Key loops

  • Lock loop (backend, every 30 seconds, and at once after a change): decides which devices are blocked from chores, hours and manual locks, and pushes the blocked MAC list to the blocker.
  • Reconcile (blocker): every 30 seconds it pulls the same list, maps MACs to current IPv4 and IPv6 addresses and applies the redirects and firewall rules. It holds no policy of its own.
  • Reports: the blocker sends devices it sees every 20 seconds and resisting devices every 15 seconds. These calls double as a heartbeat: after 90 seconds without one, the app shows "Home box offline".

Enforcement model and limits

The blocker puts itself between a paused device and the router with ARP (IPv4) and NDP (IPv6), in both directions, drops internet-bound packets with nftables and answers web requests with a captive portal. It fails open: if the box or the blocker stops, devices return online.

Does What it does

  • Pauses and unpauses devices within seconds of a decision.
  • Flags a paused device that keeps reaching the internet (for example after its network settings change) as resisting, and alerts parents.
  • Works over IPv4 and IPv6.

Doesn't What it doesn't do

  • Control phones on mobile data or a hotspot, or devices on another network.
  • Get past routers with ARP inspection or client isolation (rare, but they exist).
  • Stop a kid who uses a device you haven't set up.
  • Stop someone unplugging the box.

Data model

SQLite on the home box, defined in backend/app/models/ and migrated with Alembic. Foreign keys are on and closed value sets have CHECK constraints.

Tables by area

  • Chores: chores, chore_steps, chore_types, chore_type_notes. A chore is a reusable template.
  • Who and when: chore_assignments, assignment_kids. Mode each, race or team; repeat daily, weekly or once.
  • Today's work: chore_runs, run_kids, run_step_ticks. Runs read the title, points and steps live from the chore.
  • Proof and chat: chore_photos, threads, thread_messages, message_reactions, chat_photos.
  • Economy: points (a signed ledger), rewards, redemptions, screen_time_limits.
  • Progression: badge_awards, custom_badges, kid_flair. Levels and streaks are worked out from the ledger, not stored.
  • Network: devices, device_ipv6, device_groups, device_events, device_presence, overrides.
  • Hours: hour_rules, hour_rule_times, hour_rule_targets. School night, weekend, holiday, summer or other; online, free time or internet off.
  • Notifications: notifications (the in-app inbox), notify_places, notify_held (Apprise).
  • Family: family_settings, users, password_resets, pending_invites, used_invites.

Security notes

Auth and secrets

JWT bearer tokens for parents and kids. Passwords hashed with bcrypt; logins are rate limited. SECRET_KEY, JWT_SECRET_KEY and INTERNAL_TOKEN are generated on first boot into DATA_DIR/secrets.json (mode 0600) unless set in the environment.

Kid login

Kids sign in by device: the app matches the request's IP to a known device and its owners, then asks for a PIN if one is set. Failed tries are rate limited. X-Real-IP is trusted only from the frontend's fixed address.

Photos

JPEG, PNG or WebP up to 10 MB, checked before decoding, then re-encoded to JPEG, which strips EXIF and GPS. Stored under random names and served only to signed-in users.

Network

The blocker runs with NET_ADMIN and NET_RAW on the host network. Backend and blocker share INTERNAL_TOKEN, compared in constant time, for every call that controls blocking.

Notifications

Apprise addresses are stored encrypted and shown masked. Kid alerts go through ntfy on the box with a long random topic per kid; ntfy has no password unless you add one.

GIFs

Off by default. Only the backend talks to GIPHY, with a fixed host. The family's rating is checked again on the box for every GIF, and kids' devices never contact GIPHY.

Testing

Unit tests

Backend and blocker: pytest. Frontend: Jest. For example cd backend && python -m pytest tests -q.

Lab

An isolated Docker network with a fake router, a fake internet, the real backend and blocker, and kid devices. Tests real ARP, nftables and captive portal journeys. See lab/README.md.

Browser e2e

Playwright against the lab: bash scripts/lab.sh e2e.

CI

On pushes to main and develop, and on pull requests: lint (ruff, ESLint, tsc), backend tests, an installer smoke test, the lab, and a Trivy security scan. Keep it green.

How to add a badge or flair item

Built-in badges

Add a line to CATALOG in backend/app/services/badges.py: key, name, emoji, description, the metric it counts, and the copper-to-mega-diamond thresholds. Then add a test in backend/tests/test_badges.py. Parents make custom badges in the app, no code needed.

Flair items

Add an item to CATALOG in backend/app/flair/catalog.py with the level that unlocks it and its slot (card, ring, name, emblem or title). Non-emblem items need CSS in frontend/src/v2/flair/; animations go inside prefers-reduced-motion: no-preference.
